# 代码结构与中文注释导读

项目继续使用 Flask、Jinja、原生 JavaScript、CSS 和 MySQL，没有引入新的前端框架。中文注释解释各部分做什么、关键规则为什么这样处理；页面、接口字段、数据库标识继续使用英文。

## 建议阅读顺序

1. `app/__init__.py`：创建应用并注册路由；`app/extensions.py`：提供数据库、登录和 CSRF 工具。
2. `app/models.py`：认识账号、客户、房型、实体房、订单、房晚、价格快照、付款及审计之间的关系。
3. `app/auth.py`：公共登录注册和角色入口。
4. `app/guest.py`：客户页面；`app/frontdesk.py`：员工操作入口；`app/manager.py`：管理员操作入口。
5. `app/booking.py`、`app/desk.py`、`app/manager_services.py`：真正检查规则并写入数据库的业务服务。
6. `app/allocation.py`、`app/pricing.py`、`app/reports.py`：三个入口共享的分房、计价和统计逻辑。

## 员工工作台如何分工

`frontdesk.py` 只接收请求、校验表单、调用服务并返回结果。`frontdesk_forms.py` 集中管理各表单字段；`account_forms.py` 提供三个角色共用的改密码校验。

`frontdesk_views.py` 只准备页面数据，按以下顺序组装：

- `_selection_context`：处理日期、楼层、搜索及筛选参数。
- `_board_context`：组织房态、楼层图和时间轴。
- `_shift_context`：组织当班数字、通知及逾期到店事项。
- `_drawer_context`：决定选中订单或房间的可见操作及说明。
- `_form_context`：准备带独立前缀的表单。
- `_list_context`：计算订单与任务列表的分页。

`templates/frontdesk/index.html` 保留页面骨架，侧栏、顶部、房态、订单、任务及两类抽屉分别放在 `_*.html` 片段中。片段共用同一份上下文，表单地址与字段名保持一致。

## 用一次预订串起来

客户选房型并提交后，`guest.py` 检查输入，`booking.py` 检查客户、时间、幂等键和报价，`allocation.py` 选择一间全程可用的实体房。成功时，订单、每晚占用、每晚价格快照及审计一起提交；任一步失败就一起回滚。员工和管理员随后读取同一份记录。

分房负载是“近 30 天已经实际入住的房晚＋今天及以后的有效预订房晚”。例如三间同房型的负载是 8、3、3，先在后两间中选择最久没有成功分配的；仍相同才用房间 ID 决定稳定顺序。房态图中的摆放位置与这个实际分房算法无关。

## 重构时应保留的边界

- 数据库锁由 MySQL/InnoDB 执行；Python 负责在事务中申请锁和复查状态。
- `(room_id, stay_date)` 唯一约束必须保留，不能只依赖页面禁用按钮。
- 事务块是提交边界；失败抛异常退出，外层转换响应。死锁、锁超时等竞争错误使用新 Session 有限重试。
- 报价使用共用计价服务，旧订单使用已保存的价格快照。
- JavaScript 改善交互，后端始终检查权限、订单归属和业务规则。
- SVG 的位置由 Python 计算，文字与链接由 Jinja 自动转义；不同房间数量应全部显示，不能因走廊位置而漏画。

## 其他部分

- `app/static/*.js`：原生 DOM 与事件处理，默认用 `const`，需要重新赋值才用 `let`；员工脚本按交互分别初始化。
- `app/static/*.css`：公共、员工、管理员及房态图样式；CSS 顺序可能影响覆盖结果，不宜随意调换。
- `app/templates/shared/`：两个工作台共享的 SVG 及单间房模板。
- `migrations/`：数据库升级链；本次风格重构没有新增结构版本，旧迁移只补充了中文说明。
- `tests/`：真实 MySQL 集成测试，各文件顶部说明覆盖范围。`test_floorplan.py` 额外验证漏房、坐标范围及文本转义。
- `requirements*.txt`：固定依赖及测试依赖。PowerShell 启停脚本只用于本地开发，路径和端口需要与自己的环境对应。

## 验证方式

先按 README 准备一个独立的空 MySQL 测试数据库，设置 `TEST_DATABASE_URL` 后运行 `python -m pytest`。测试会执行数据库迁移，不使用日常演示数据库。结构一致性使用 `flask db check`；JavaScript 可以用 `node --check 文件路径` 检查语法。

本轮重构沿用课件的文件职责和模板复用思路：`COMP3019J_Week3_Flask.pdf` 物理第 30–37、64 页；`const/let` 的基本用法见 `COMP3019J_Week6_JavaScript_and_DOM.pdf` 物理第 11 页。具体模块拆分和并发处理是本项目的工程实现，不是课件原代码。
